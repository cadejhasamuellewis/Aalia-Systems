# Replit Addendum — Use With the Universal Instructions

## 1. Purpose

Use this addendum when planning, building, testing, reviewing, or deploying a project in Replit.

## 2. Before Building

1. Inspect the current Replit project and files.
2. Identify the plan, workspace, deployment type, database, storage, secrets, and connected repository.
3. Confirm whether the project is new or an existing build.
4. Create or confirm a backup, checkpoint, branch, or repository baseline.
5. Identify paid features and usage-based costs.
6. Separate real functionality from visual placeholders.

Do not assume a visible screen works.

## 3. Replit Plans and Agent Work

Before approving a build phase, confirm:

1. What Replit plans to change
2. Files and routes affected
3. Authentication and permission impact
4. Database and migration impact
5. Costs
6. Tests
7. Backup and rollback
8. What remains a placeholder

Do not approve broad prompts that allow unrelated rewrites.

## 4. Cost Control

Explain before using:

- Agent credits
- Deployments
- Databases
- Object storage
- Email services
- Monitoring
- AI APIs
- Paid integrations
- Autoscaling or usage-based resources

Do not create paid resources without approval.

## 5. Publishing

Do not publish automatically.

Before publishing:

1. Confirm the correct project and account.
2. Run tests.
3. Verify secrets are configured safely.
4. Confirm domain and DNS plan.
5. Confirm rollback.
6. Confirm costs.
7. Obtain approval.

## 6. Review Categories

Every Replit review must classify findings as:

1. Verified working
2. Partially working
3. Visual placeholder
4. Planned
5. Missing
6. Blocked
7. Unverified

## 7. Handoff

Maintain a private source-control backup when possible.

Document:

1. Run command
2. Test command
3. Environment variable names
4. Deployment setup
5. Database setup
6. Known limitations
7. Costs
8. Recovery steps
